# 架构文档反向同步（NestJS）

## 适用场景

- 代码已新增 / 删除模块，需要把变化反映到《架构设计说明书》
- 需要生成"后端模块清单"与"接口清单"两张表
- 答辩前核对"文档与代码一致"这一评分项

## 前置条件

- 后端代码已按模块结构放在 `backend/src/modules/<功能模块>/` 下
- 目标文档章节为 L2 功能结构图、V2 源码目录、L6 接口定义

## 执行步骤

1. 运行 `scripts/scan-structure.py backend/src`
2. 将输出的"后端模块清单"表格粘贴到 V2 源码目录章节
3. 将"接口清单"粘贴到 L6 接口定义章节，并与 `docs/api/openapi.yaml` 互相比对
4. 发现文档与代码不一致时：先判断以代码为准还是以文档为准，再修改落后一方
5. 在 `usage-log.md` 记录本次同步改了什么、为什么

## 本项目强制约束（违反即视为错误）

- 只扫描 `backend/src/modules` 下的一级子目录作为功能模块，不得把 `dist/` 生成物计入
- `entity`、`dto` 是模块内部结构，不算独立功能模块
- 扫描结果必须与 V2 源码目录一一对应，出现"代码有、文档无"或"文档有、代码无"都要处理
- 不手工编造接口清单，必须以 Controller 的 `@Get/@Post/@Put/@Delete/@Patch` 装饰器为准

## 输出物

- Markdown 格式的后端模块清单表
- Markdown 格式的接口清单表

## 自检清单

- [ ] 模块清单覆盖所有 `modules/` 一级子目录
- [ ] 接口清单与 Controller 路由一致
- [ ] 文档与代码无"有 / 无"不一致
- [ ] 扫描脚本无需第三方依赖可直接运行

## 常见错误与反例

- 错误：把 `entity`、`dto` 当成一级功能模块 → 模块划分失真，功能模块数量虚高
- 错误：手写模块清单导致遗漏 → 文档与代码脱节被扣分
- 错误：扫描目录传错，扫到 `dist/` → 清单里出现重复文件
